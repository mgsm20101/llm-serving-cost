# مذكرة تقنية: تكلفة وأداء نماذج LLM — على الخادم المحلي أم الـ API؟

**إلى:** CTO / Technical Leadership  
**من:** فريق Applied AI  
**التاريخ:** 2026-06-13  
**الموضوع:** تحليل تكلفة/أداء لنماذج LLM المحلية مقابل الـ Cloud API

---

## الملخص التنفيذي

قِسنا أداء نموذج محلي واحد (`qwen3:4b`) على جهاز محمول (i7-8750H · 15.9 GB RAM ·
GTX 1050 Ti 4 GB) عبر Ollama — **6 تشغيلات**، مقابل أسعار Cloud API (GPT-4o-mini كمعيار).

**النتائج الرئيسية:**
- **~4 tok/sec و ~75 ثانية حتى أول token** — وهذا زمن batch job، لا زمن محادثة.
- نقطة تعادل التكلفة مع API تقع عند **119,048 token/شهر** — محسوبة من
  `$50/شهر ÷ $0.42/1k` (سعر مخلوط: 40% input + 60% output).
- **التوصية:** API تحت ~120k token/شهر. فوق ذلك، التقييم يحتاج قياساً على عتاد الخادم
  المستهدف قبل أي قرار شراء.

## مقاييس الأداء — المقيس فعلاً

المصدر الوحيد: [`results.md`](results.md) — 6 تشغيلات، نموذج واحد.

| الموديل | فئة الطلب | Avg TTFT | Avg tok/s |
|---------|:---------:|:--------:|:---------:|
| `qwen3:4b` | قصير | 75,306 ms | 3.96 |
| `qwen3:4b` | متوسط | 73,499 ms | 4.09 |
| `qwen3:4b` | طويل | 76,657 ms | 3.92 |

**ملاحظة على TTFT:** طول الطلب لا يكاد يحرّك الرقم — أي أن العنق ليس prefill، بل
decode لكل token. و~75 ثانية انتظار قبل أول حرف مقبولة في batch job وغير مقبولة
إطلاقاً في استخدام تفاعلي.

> **ما حُذف من هذه النسخة:** جدول سابق يذكر `~5s` لـ `qwen3:4b` وصفاً لـ
> `qwen2.5:7b-instruct` لم يُقس أصلاً. الرقم الأول يناقض قياس هذا المشروع نفسه بنحو
> 15×، والثاني بلا ملف نتائج. كذلك حُذف تعادل «~290,000 token/شهر» لأنه لا ينتج عن
> نفس المعطيات المعلنة ($50 ÷ $0.42/1k = 119,048).

## نموذج التكلفة

### افتراضات الخادم المحلي
```
خادم مفترض للنشر — وليس جهاز القياس (8-core, 32GB RAM):
  - إيجار سحابي مكافئ: ~$50/شهر
  - أو: hardware $800 × amortized 3 سنوات + كهرباء = ~$30/شهر
  - المعتمد في التحليل: $50/شهر (worst case)
```

### API Pricing (GPT-4o-mini، 2026)
```
Input:  $0.15 / 1M tokens = $0.00015 / 1k
Output: $0.60 / 1M tokens = $0.00060 / 1k
Blended (40% input / 60% output): $0.42 / 1k tokens
```

### نقطة التعادل
```
$50 (local/month) = X tokens × $0.00042/token
X = 50 / 0.00042 = ~119,000 tokens/شهر

=> إذا كنت تولّد أكثر من ~120k token/شهر، الخادم المحلي أرخص.
```

## إيجابيات وسلبيات

### الخادم المحلي (On-Prem / Self-Hosted)
✅ **تكلفة ثابتة** بغض النظر عن الحجم  
✅ **خصوصية البيانات** — البيانات لا تغادر الشبكة  
✅ **latency منخفض** لو في نفس الـ datacenter  
✅ **تحكم كامل** في الموديل والإصدار  
❌ **رأس مال مبدئي** للـ hardware  
❌ **عبء التشغيل** (devops, updates, monitoring)  
❌ **لا scalability فورية** لو ارتفع الحمل فجأة  

### Cloud API
✅ **Pay-as-you-go** — لا تدفع وقت الخمول  
✅ **Zero ops** — لا تشغيل، لا صيانة  
✅ **أحدث الموديلات فوراً**  
✅ **Scale فوري** إلى ملايين الطلبات  
❌ **تكلفة تتزايد مع الحجم**  
❌ **اعتماد على طرف ثالث** (availability, pricing changes)  
❌ **البيانات تغادر الشبكة** — قد يكون مشكلة compliance

## التوصية النهائية

**للأشهر الأولى:** ابدأ بـ API (صفر ops، ادفع فقط ما تستخدم).  
**عند تجاوز 500k token/شهر:** قيّم GPU server محلي — يُسترد في 3-6 أشهر.  
**للبيانات الحساسة (قانوني/صحي/مالي):** on-prem من اليوم الأول بصرف النظر عن الحجم.  
**نموذج هجين:** API للطلبات الفورية + local GPU للـ batch jobs الليلية.
