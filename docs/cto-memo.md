# مذكرة تقنية: خادم محلي أم API؟

**الموضوع:** تكلفة وزمن تشغيل نموذج لغوي محلياً مقابل API مستضاف
**المصدر الوحيد للأرقام:** [`results/bench_f6042d92.json`](../results/bench_f6042d92.json) — commit `f6042d92`، شجرة نظيفة.

## الخلاصة

- على هذا الجهاز (Windows 11, 15.9 GB RAM, NVIDIA GTX 1050 Ti 4 GB (Ollama GPU offload)) نموذجان صغيران (`gemma3:4b` و`qwen2.5-coder:3b`)
  يعطيان أول token في أقل من 1.2 ثانية بعد التحميل، وحوالي 8–10 token/ثانية.
- نقطة التعادل مع API بالأسعار المفترضة (~$50/شهر للخادم، $0.42 لكل مليون token مخلوط)
  هي **~119 مليون token/شهر**. سعة الجهاز المقيسة لو اشتغل 24 ساعة طول الشهر **~22–25 مليون**.
  يعني التعادل **غير قابل للوصول** على هذا العتاد: الـ token المحلي أغلى بحوالي 4.7–5.5×.
- **التوصية:** على عتاد بهذا المستوى، التشغيل المحلي يُبرَّر بسرية البيانات أو العمل بدون
  إنترنت، مش بالتكلفة. أي قرار شراء يحتاج قياساً على الخادم المستهدف نفسه.

## الافتراضات — مدخلات مش قياسات

- تكلفة الخادم الشهرية ($50) افتراض لخادم نشر مخصص، مش جهاز القياس.
- أسعار الـ API للتوضيح ($0.15 / $0.60 لكل مليون token دخل/خرج، بنسبة 40/60). السعر
  بالمليون هو الوحدة اللي بينشرها المزوّدون.

## تصحيح

نسخة سابقة من المذكرة كانت بتقول إن التعادل عند ~119 **ألف** token/شهر. السبب إن السعر لكل
مليون اتعامل كأنه لكل ألف، فطلع الرقم أصغر 1000×. الوحدة دلوقتي مكتوبة في اسم كل parameter
وعليها test. والأرقام القديمة للزمن كانت لنموذج تاني ومن غير ملف نتائج، فاتشالت.

## ما لا تثبته المذكرة

- طلب واحد في كل مرة، ما فيش اختبار تزامن.
- نموذجان صغيران على لابتوب واحد؛ خادم بـ GPU أقوى هيغيّر السعة، وبالتالي الاستنتاج.
- جودة الإجابات ما اتقاستش هنا.
